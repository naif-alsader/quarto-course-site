THE REVEAL

Why Typst and not LaTeX: no TinyTeX download at render time. On the air-gapped box that is not a preference, it is the only thing that works.

Word is not a compromise

The old loop

You write. You export. They edit the export. You retype their edits into your analysis.

The new loop

You render to Word. They track changes. You read the changes and edit the source. Re-render.

format:
  docx:
    reference-doc: templates/gastat-reference.docx

Twenty-five minutes. This is the segment that makes managers say yes, so do not rush it.

The reference-doc is a Word file with GASTAT’s styles defined in it — Heading 1, Body Text, Caption. Pandoc reads the styles, not the content.

Be honest: the reviewer’s edits do not flow back automatically. You read them and change the source. What you never do again is retype a number.

Where the promise gets complicated

::: {.content-visible when-format="html"}
A leaflet map the reader can pan.
:::

::: {.content-visible unless-format="html"}
A static choropleth, same data, same code until the last line.
:::
  • .content-visible when-format= / unless-format=
  • .content-hidden when-format="docx" — the note reviewers see and the public does not
  • knitr::is_html_output() inside a chunk
  • eval is different: content-visible hides output, eval decides whether the code runs at all

“One source, many formats” is not free. This is where you manage the seam.

Thirteen minutes. Spend the last three on eval: one distinction, one example, move on. Hiding output and not running code are different problems, and people reach for the wrong one.

The honesty is the teaching: a room of statisticians will find the seam within a week of going home, and if you pretended it was not there they will stop trusting the rest.

Parameters

One template, many reports

By the end of this block they can turn a constant into a parameter and drive a batch render from R.

THE REVEAL

Jazan and Riyadh, side by side. One file made both.

Five minutes. Open bulletin-jazan.pdf and bulletin-riyadh.pdf next to each other.

Read the two headlines aloud. In Jazan the rate rose; in Riyadh it fell. The sentences say so, in opposite words, and nobody wrote either one.

Then the question that opens the block: “Yesterday you had a file with REGION <- \"Jazan\" in it. What is the smallest change that makes it produce both of these?”

Let someone answer before you show the next slide.

Promote the constant

Yesterday your bulletin began:

REGION <- "Jazan"          # a constant in a chunk

Today it begins:

params:
  region: "Jazan"          # a knob on the outside of the file
REGION <- params$region

That one move is the whole of parameterisation.

Do this live, in their Day 1 file. Two lines change. Render with -P region:Riyadh from the terminal and show the same file producing a different report.

Fifteen minutes, and most of it is them doing it, not you.

Parameterising an argument

A descriptive caption parameterises for free:

“Unemployment by quarter, r params$region”

A message caption does not. Jazan rose; Riyadh fell; a third region did neither. One sentence cannot be all three.

THRESH <- 0.5                     # points. Stated, never zero
change <- last(this_r$rate) - first(this_r$rate)

trend_title <- if (change > THRESH) {
  sprintf("%s has moved against the national trend", REGION)
} else if (change < -THRESH) {
  sprintf("%s tracked the national decline", REGION)
} else {
  sprintf("%s was broadly unchanged", REGION)
}

trend_title
[1] "Jazan has moved against the national trend"

Ten minutes, and this is the hardest idea in the three days.

Day 1 said a caption is an argument. Day 2 says one template, many reports. Those two collide, and this is the resolution: in a parameterised report every message caption is either computed by rule or demoted to a descriptive label. You pick, knowingly.

Show the real code in bulletin.qmd. It is about forty lines and it is the most valuable forty lines in the project.

Then change REGION to "Riyadh" and re-run in front of them. The same six lines, the opposite sentence, and nobody edited prose. That is the whole slide.

Two warnings, and they matter more than the code:

  1. A rule you have not tested on all thirteen regions will publish a false sentence. That is worse than a dull one.

  2. The third branch is the one nobody writes. A two-way rule gives a region that neither rose nor fell a false sentence either way. THRESH is stated and never zero — below it the series has not moved in any sense a reader should act on.

    Be honest about it: in this synthetic set every region moved at least 2.1 points, so the third branch never fires. It is there for GASTAT’s real figures, where flat regions are ordinary. A branch you cannot trigger is a branch you have not tested — bulletin.qmd uses the same rule and it was tested against all three outcomes separately.

The render script is the pipeline

render_one <- function(region, fmt = "typst") {
  quarto::quarto_render(src, output_format = fmt,
                        execute_params = list(region = region))
  file.rename(produced, dest)      # Quarto always writes bulletin.<ext>
}
regions |> purrr::walk(render_one)

Thirteen renders, thirteen files called bulletin.pdf. Move each one as it appears.

Twenty-five minutes — Block 1’s conditional segment gave us ten of them, and this is where Lab 2 actually fails, so spend them here.

Two traps, both real, both in our own render.R:

  1. Quarto writes next to the source, always as bulletin.pdf. Rendering thirteen regions means thirteen files with the same name. You must move each one as it appears.
  2. Two renders at once fight over that file. Our script takes a lock and fails loudly.

Show render.R. It is forty lines and it is the pipeline.

Naming the output

“Northern Borders” is not a filename.

Thirteen regions, thirteen filenames, from a rule you write once.

One minute here, then build it live — the next five slides are that build.

It sounds trivial. It is the thing that breaks their first real batch run.

Naming the output

region
[1] "Northern Borders"

One of the thirteen, exactly as it appears in regions.csv.

Ask before moving on: what is the filename for this region? Someone will say Northern Borders.pdf. Let them.

Naming the output

slug <- gsub("[^A-Za-z0-9]+", "-", region)
slug
[1] "Northern-Borders"

[^A-Za-z0-9]+ is everything that is not a letter or digit, collapsed to one hyphen.

The space is gone. Read the value out loud — it is still capitalised.

Naming the output

slug <- gsub("[^A-Za-z0-9]+", "-", region)
slug <- tolower(slug)
slug
[1] "northern-borders"

Lower case. Now it is a slug: safe in a shell, a URL, and SharePoint.

This is where the rule fails for the Arabic family — the pattern strips every Arabic character and leaves an empty string. Key those off region_code instead.

Naming the output

slug <- gsub("[^A-Za-z0-9]+", "-", region)
slug <- tolower(slug)
dest <- file.path(out_dir, sprintf("bulletin-%s.%s", slug, ext))
dest
[1] "_out/bulletin-northern-borders.pdf"

And the filename. A display name has become something a script can use.

This is the rule. It goes in the render script once and you never think about it again.

Naming the output

slug <- tolower(gsub("[^A-Za-z0-9]+", "-", region))
dest <- file.path(out_dir, sprintf("bulletin-%s.%s", slug, ext))

Two lines. They go in render.R and you never touch them again.

The reference version — the two lines re-nested back to their original form, exactly as they appear in artifacts/family/render.R.

The build unnested them so each step could print; this is what you actually write. Same result, and it is worth saying so rather than letting anyone think the four-line version is the real one.

No output here: both lines are assignments. That is the point of the build.

By the end of this block they can move brand, language and environment out of the document and into project files.

THE REVEAL

Change one line. Re-render. Watch the institution change colour.

Change it back. Re-render.

_brand.yml

color:
  palette:
    indigo: "#4137A8"   # the template's title-slide ground
    green:  "#00B050"   # the signature accent
    dark:   "#2C2D3F"

This file branded the bulletin, the family, and these slides.

Fifteen minutes. Open _brand.yml, change the green to something awful, re-render one bulletin, show it, change it back. The room needs to see that identity is one file.

The institutional argument: the person who knows the house style leaves. The file stays.

Language is also a file

lang: ar
dir: rtl

Verified

Arabic HTML, Word, Revealjs, and Typst PDF — prose, tables, bidi with Latin numerals.

Known limits

rtl: true breaks ?print-pdf. Tajawal covers Latin and Arabic, so the Arabic edition needs no substitute face.

Fifteen minutes. Show spike/rtl-prose.pdf — this was tested, not assumed, and the evidence is in the repo.

Raw ```{=typst} blocks with #set text(dir: rtl) leak direction into everything after them. Ordinary markdown with dir: rtl in the YAML does not. Teach the second.

The environment is a file too

renv

renv.lock pins every package version. Restore it and you have the machine the report was written on.

freeze

Chunks do not re-run unless their code changed. A render stops meaning a re-analysis.

Brand, language, environment. None of them live in the document.

Ten minutes. This closes the block’s argument: three things that used to be habits are now files.

freeze: auto is the one they will thank you for on a slow box — and it is what stops the Hive extract running on every render.

What this course did not teach you

Git.

RAP is code, version control, a reproducible environment, no manual steps. We have covered three of the four.

  • Quarto makes the report reproducible — that was Day 1’s honest limit
  • renv makes the environment reproducible — that was five minutes ago
  • Version control is the gap, and it is a separate day

Ask the platform team. Do not start without it.

Six minutes, and the honesty is the point.

Day 1 said out loud that Quarto does not make your analysis reproducible. If git then never appears in three days, that line reads as an excuse rather than a limit.

Name it, say where to get it, and move on. Do not teach git badly in six minutes.
